# AniPM 0.1.3 reviewed release

Compatible with released App Store Aroki 2.1.36 and the newer 2.1.37 reader, without changing the app engine. Connector ID and family remain `anipm`; this is an in-place upgrade. Readers below 2.1.36 keep installed older modules rather than accepting an unsupported update.

Exact manifest SHA-256: `49ee962133d6963439c75a896a49c28b6acad1a4c4aaa0ecec332b8a5c88245d`.

The existing bootstrap response now has two required bounded context checks: the requested audio's availability must be true, and its effective language must match the requested Sub/Dub variant. Both checks use the already-shipped typed-context and template primitives, adding zero requests, no new hosts and no JavaScript. A conflicting or missing declaration stops before session creation; there is no implicit Dub-to-Sub substitution. Existing routing, episode mapping, headers, supplied captions and session expiry are unchanged.

Live profile: 38/50 (76%) frozen released-title samples passed both bounded HTTP media validation and macOS native-player advancement. Eight failed with HTTP 404 along the selected title chain; four had no strict verified title match and remain unresolved, not confirmed absent. All 50 remain in the denominator. No rate-limit/access-refusal halt occurred. This is a different corpus from the earlier 42/50 baseline; those scores must not be presented as a paired improvement/regression.

Corpus SHA-256: `27857cf9be9aed1df4add9425f38d350e4b225af006350bcfa34c77f00945314`. It was frozen prospectively from released-status catalogue metadata, covering popular/current/classic/niche/film categories, before this candidate's playback tests. The attached redacted report preserves all failures.

Static comparison with official Player AniPM beta9 found the same search-ID to series-route mapping. That does not establish the exact provider-side cause of the 404s and does not justify inventing replacement IDs.

Deterministic tests cover valid Sub and Dub, missing/false/malformed availability, missing/unknown/opposite effective language, no session on rejected audio, 429 stop, candidate-to-baseline semantic equality and unchanged caption/expiry handling. Actual ConnectorStore fresh install, update and restart passed for 2.1.36 and 2.1.37 while preserving one installed family and rollback bytes. The combined native regression suite passed 593 tests with 22 skipped and zero failures; the final portable fixtures passed a further 14 focused tests.

Supplemental live Dub checks: Naruto episode 1 advanced natively on an explicit Dub request; Dawang Raoming episode 1 Dub was rejected at `audioAvailable`, not silently played as Sub. These checks are reported separately from the 50-title profile and do not verify spoken language.

Limitations: this is not a physical-device playback result or proof of spoken language/full subtitle synchronisation/every episode/quality. The old app may still display its generic error/retry UI for rejected audio; this module does not add a greyed-out Dub toggle or a new typed engine error. The source's missing titles are not claimed fixed.
